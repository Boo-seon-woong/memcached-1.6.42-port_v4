# 확장 span latency — 측정·분해·해결 (KTC 0806, 목표 1)

전부 기측정 원장 발췌(새 측정 없음). 잰 적 없는 값은 공백(—)으로 두고 §5 에
모았다. 단위 µs. 서사는 [`V3_TO_V4_CHANGES.md`](V3_TO_V4_CHANGES.md).

```text
span v2   장치가 일한 시간         GET: post→복호           SET: seal→CQE
span v3   원격화가 추가한 일 전체   GET: 진입→복호           SET: 진입→WFLIGHT 해제
          기준: "로컬 메모리였으면 하지 않았을 일 전부".  재정의 2026-07-31 밤
성분      v3 = admit + v2 (+ret)   독립 집계, 합 검사 성립 (242.28 vs 242.29)
          v2 = sync + xfer + crypto + 잔차 — xfer·sync 는 배치 공유값이라
               GET 은 비가산(잔차 −26.2% 실측), SET 은 −1.1%로 완전 분해
클라측    que + pre + [span v3] + post — 계측이 2026-08-04(v4) 신설, v3 시대 전무
```

## 3. [1-3] v3 워크플로 — 대기 지점과 해결

```text
GET                              성분        SET                              성분
① read·파싱·해시                 (밖)        ① read·값 수신·파싱               (밖)
② storage_get_item() 진입   ◀v3 ┐           ② storage_store_item_pac() ◀v3  ┐admit
③ io_queue 삽입                  │admit      ③ 원격 슬롯 확보·stub            ┘0.5~0.7
④ ── pass 끝까지 대기 ──         │217~285    ④ pac_seal                 ◀v2  ┐
⑤ 일괄 submit→window·slot        ┘           ⑤ stub 게시(WFLIGHT)→그 자리 post│v2 7.7~16.9
⑥ ibv_post_send            ◀v2  ┐v2         ⑥ CQE 관측→주차            ▶v2  ┘
⑦ RDMA 왕복                      │25~27      ⑦ ── if(out)인 pass 대기 ──      ret 173~2372
⑧ pass 끝 drain: CQE·복호  ▶둘다┘           ⑧ WFLIGHT 해제             ▶v3
⑨ 재개→응답                      (밖)        ⑨ 재개→STORED                    (밖)
```

- **GET admit**: 제출 조건 "연결 20개"(`memcached.c:3324`)가 스레드당 4연결
  구성에서 발화 불능 → 전부 pass 끝 대기, pipeline 깊이에 비례.
  해결(v4): `ext_submit_inline` — io_queue 우회, 파싱 자리 post(20 은 불변).
  배칭은 `ext_post_chain=8`/`ext_reap_every=8` 로 재구성.
- **SET ret**: 재개가 `thread.c:531` `if(out)` 안에만 있는데 SET 제출 경로가
  CQ 를 스스로 비워 `out==0` → 블록 통째 스킵.
  해결(v4): 거둔 자리 즉시 실현(trylock 프로브) + pass 끝 무조건 flush.
  ret 2371.84 → 0.14 (커밋 `3a50784`).
