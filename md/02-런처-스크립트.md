# SEV-SNP guest 기동 절차

실험용 guest(24 vCPU / 48 GB / SNP / HCA passthrough)를 마지막 성공 실험
(2026-07-24, 2026-07-27)과 동일한 상태로 띄우는 전체 절차다. 명령은 host 1개,
guest 6개가 전부다.

Claude 세션은 host 명령을 `sudo guestctl.sh {up|down|status}`로 실행한다 —
이 세 개만 NOPASSWD sudoers에 등록돼 있고, `up`은 아래 §1과 동일한
`--direct-kernel-boot` 기동이다.

> **핵심: 반드시 `--direct-kernel-boot`로 띄운다.**
> `run_sev_snp_rdma.py`의 기본값은 firmware boot이고, 그 경로는 guest 내장
> grub이 **stock 6.8-generic 커널**로 부팅한다. 그 커널에는 coherent CQ 패치가
> 없어서 Port engine이 `create_cq failed: Invalid argument`로 죽는다
> (2026-07-27 실제 발생). 실험 커널 `6.16.0-snp-guest-038d61fd6422`는 guest
> `/boot`에 없고 host에서 `-kernel`로 직접 주입된다.

## 1. Host: 기동

```bash
cd ~/2026/sev
sudo python3 run_sev_snp_rdma.py --direct-kernel-boot
```

- qemu가 foreground로 돌므로 유지하려면 tmux 안에서 실행하거나
  `sudo nohup python3 run_sev_snp_rdma.py --direct-kernel-boot >/tmp/snp-guest.log 2>&1 &`
- 커널/initrd: `~/2026/sev/boot/noble/vmlinuz` → `vmlinuz-6.16.0-snp-guest-038d61fd6422`
- HCA `0000:c1:00.0`을 vfio-pci로 바인딩해 passthrough하고, qemu 종료 시
  host driver로 자동 복구한다
- guest ssh는 `localhost:2222`로 포워딩된다

## 2. Guest: 부팅 후 1회 설정

```bash
ssh -i ~/.ssh/snp_guest -p 2222 ubuntu@localhost

uname -r    # 6.16.0-snp-guest-038d61fd6422 이어야 한다. 6.8-*이면 잘못 부팅된 것

sudo insmod ~/pb-guest/snp_shared-6.16.0-snp-guest-038d61fd6422-cachemode.ko
sudo rmmod mlx5_ib && sudo insmod ~/covlib/mlx5_ib.ko   # 2026-07-24 build
sleep 3                                                  # ibp1s0 재생성 대기
sudo ip addr add 10.99.0.3/24 dev ibp1s0                 # genie memnode는 10.99.0.2
sudo ip link set ibp1s0 up
ping -c 2 10.99.0.2
```

- `snp_shared`가 `/dev/snp_shared`(decrypted shared page)를 만든다. coherent
  QP/CQ 버퍼가 여기서 나오므로 없으면 `create_cq EINVAL`로 죽는다.
- 패치 mlx5_ib는 **`~/covlib/mlx5_ib.ko`(2026-07-24 build)** 하나뿐이다.
  `~/mlx5_ib.ko`(7/6)와 `/lib/modules/6.16.…`(5/10)는 구버전이고, 구버전으로는
  snp_shared가 있어도 `create_cq EINVAL`이 난다 (2026-07-27 실측).
- **mlx5_ib를 교체하면 `ibp1s0`이 재생성되어 IP가 사라진다.** 반드시 모듈 교체
  → IP 부여 순서로 한다. IP는 재부팅마다도 사라진다.

## 3. 검증: 실제 rdma_cm 연결 smoke

`/dev/tcp`·`nc` 같은 TCP 체크는 rdma_cm 리스너 검증이 안 된다
(2026-07-27 conversation 기록 — false negative 전례). Port binary로 직접 연결한다:

```bash
cd ~/kvs-port
LD_LIBRARY_PATH=$HOME/covlib:$HOME/kvs-port MLX5_COHERENT_QP=1 MLX5_COHERENT_CQ=1 \
EXT_RDMA_PROF=1 EXT_CRYPTO_KEY=$HOME/kvs-port/ext.key EXT_SLOT_SIZE=256 EXT_READ_SLOTS=64 \
./spanv2-pool-crypto-qpaff-iolock/memcached -p 11311 -U 0 -t 2 -m 256 -c 1024 -R 1024 \
  -o ext_path=10.99.0.2:11212:4g,ext_threads=1,ext_io_depth=1 > /tmp/smoke.log 2>&1 &
sleep 5; tail /tmp/smoke.log; kill %1
```

정상이면 `genie_connect OK (raddr=… rkey=… size=4294967296)`가 찍히고 서버가
살아 있다. 아래는 전부 2026-07-27에 실측한 증상이다.

| smoke.log 증상 | 원인 |
|---|---|
| `genie_connect OK` + 기동 유지 | 정상. 실험 진행 가능 |
| `create_cq failed … Invalid argument`, dma_alloc 로그 없음 | `/dev/snp_shared` 없음 — snp_shared 미로드. stock 6.8 커널이어도 동일 증상 |
| dma_alloc은 성공 후 `create_cq failed … Invalid argument` | mlx5_ib가 구버전 — `~/covlib/mlx5_ib.ko`(7/24)로 교체 |
| `ADDR_ERROR (status -19)` | `ibp1s0` IP 소실(모듈 교체로 재생성됨) → 라우트가 NAT(enp0s2)로 샘. IP 재부여 |
| rdma_cm hang | `MLX5_COHERENT_QP/CQ=1` 또는 covlib `LD_LIBRARY_PATH` 누락 |
| `connect genie` 실패 (create_cq는 통과) | genie_memd(`10.99.0.2:11212`)가 안 떠 있음 — genie 쪽 확인 |

## 4. 종료

```bash
ssh -i ~/.ssh/snp_guest -p 2222 ubuntu@localhost sudo poweroff
```

qemu가 함께 종료되고 launcher가 HCA를 host driver로 복구한다.
