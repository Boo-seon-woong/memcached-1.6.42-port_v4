# exp2 — 성능 축(a) + 지연 분해(b) + 커넥션 교환(c) + E0

## E0 — `ext_drain_empty_max` 확정 (PENDING 블록 1, **모든 측정보다 먼저**)

코드 주석이 "측정으로 정한다"(memcached.c:267)인 채 0(무중단 스핀)으로
남아 있고, 저부하 CPU 의 대부분이 스핀이다(pipe=1 에서 busy 22.3/30 인데
0.575 M). 이 값이 exp2(b) 저부하 수치에 그대로 실린다.

```text
셀    E0-{0,4,16,64}-P{1,32}     GET-only, 30초, 값마다 서버 재기동     8 부하
판정  pipe=32 처리량 −1% 이내인 후보 중 pipe=1 busyCPU 최소값. 동률이면 큰 값
이후  확정값을 전 캠페인 서버 라인에 고정 (PLAN 공통 규약)
```

## (a) 축별 성능 — **신규 셀 없음. 조립 명세다**

throughput-latency 곡선의 offered-load 축은 `pipeline` 이고, `mcT`/`nqp` 는
점 가족이다. 전부 기존·대기 캠페인이 생산한다:

| 축 | 데이터 소스 | 상태 |
|---|---|---|
| pipeline 곡선 (PROF=0) | exp1 PT-P{1..384} 7점 | PENDING 블록 7 |
| pipeline 곡선 (PROF=1, 세분 포함) | shape C1 스윕 | 블록 2 에서 C1-128/256 창 보충 |
| mcT(=mtT) 확장 — SMART Fig.13 | shape C2 6셀 | PENDING 블록 2 |
| nqp·형태 (곱 16/32/64/128) | shape A 계열 | 〃 |
| QP 수 × depth=1 | shape B 7셀 | 〃 |
