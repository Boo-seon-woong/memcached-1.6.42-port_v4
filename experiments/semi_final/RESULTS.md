## 4. 형태 효과 — **판정 보류**. 큐 크기와 교란됐다 (2026-08-07 철회)

> **철회 사유.** 아래 두 쌍은 통계적으로는 깨끗했지만 **셀마다 CQ 크기가
> 달랐다.** 당시 CQ 는 `2 × W × nqp` 였고 `W = nqp × ORD` 였으므로 할당이
> nqp² 로 커진다. 두 쌍 모두 **이긴 쪽이 큐도 작았다** — Q1 은 CQ 32 인데
> O4 는 128(4배), S16x16 은 8,192 인데 S32x8 은 16,384(2배)다. 게다가 ATTR
> 에서 큐가 53배일 때 −2.8% 였으니 부호까지 같은 방향이다. 즉 관측된
> +1.9% 중 얼마가 형태 몫이고 얼마가 큐 몫인지 이 데이터로는 못 가른다.
> W 수정(2026-08-07, sha 646ff2b7)으로 CQ 가 `2×W+8` 이 되어 nqp 와 무관해졌으니,
> Q·O·S 세 축을 새 빌드로 다시 찍으면 판정된다.

곱과 발자국을 고정하고 형태만 바꾼 두 쌍. 복제로 군을 만들었다.

```text
wire 16 · slots 64            wire 256 · slots 512
  1×16   13.096  13.060         16×16   12.539  12.514
  4×4    12.806  12.863         32×8    12.288
  ─────────────────────         ─────────────────────
  군내 0.28% / 0.45%            군내 0.20% / (단일)
  차   +1.90%  겹침 없음        차   +1.94%  겹침 없음
```

두 쌍 모두 **군이 겹치지 않고**, 군내 폭이 군간 차의 1/4 이하이며,
차이가 재현성(0.9%)의 두 배다. wire 규모가 16 배, 발자국이 8 배 다른
두 지점에서 부호와 크기가 같다.

> **읽을 수 있는 것까지:** "곱이 같아도 구성이 다르면 다르다"는 성립한다 —
> 두 쌍 다 유의하게 갈렸다. 다만 그 차이를 **형태(QP 수 대 깊이) 때문이라고
> 귀속할 수는 없다.** 큐 크기가 같이 움직였기 때문이다.

한계: 세 번째 점 `S64x4` 가 측정 불가(§5-3)라 단조 추세 검정은 못 했고,
`S32x8` 은 단일 측정이다. 클라이언트 쪽 같은 원리는 E 축이 훨씬 큰
규모(−66.6%)로 보여주는데, **E 축은 서버를 건드리지 않으므로 이 교란이
없다** — 형태가 중요하다는 주장의 근거는 지금 E 축이 진다.

## 5. 이 침대의 한계 4건

### (1) ORD>16 핀은 무장 불가 — 계획 6점 측정 불가

```c
extstore.c:644   .responder_resources = (uint8_t)ask, .initiator_depth = (uint8_t)ask
```

핀 값이 소프트 게이트(`extstore.c:813`)로만 쓰이지 않고 **CM 연결
파라미터로도** 들어간다. ORD 는 연결 시점에 QP 에 박히는 하드웨어 속성이라
소프트웨어로 올릴 수 없다. 실패는 두 갈래다.

```text
ORD 32 · 64 · 128   rdma_connect: Invalid argument
                    장치 max_qp_rd_atom(16) 초과라 CM 이 연결을 거부한다
ORD 256             connect OK → 첫 READ 가 remote invalid request (9)
                    (uint8_t)256 == 0 으로 잘려 READ 능력 0 인 QP 가 선다
```

`extstore.c:650` 주석의 "초과분은 SQ 에 쌓인다"는 실측으로 거짓이다.

측정 불가: `O32 O64 S1x256 S2x128 S4x64 S8x32`.
고치려면 CM 파라미터만 HCA 최대로 clamp 하고 소프트 게이트는 핀 값을 쓰면
된다(주석이 의도한 동작). **캠페인 중 바이너리 교체는 하지 않았다** —
지문 sha 가 바뀌면 앞선 셀 전부와 비교가 끊긴다.

### (2) 구동기 `SS` 누수 — T 축·OP-r2 발자국 4배, 영향 1.4%

`sf-resume.sh:187` 의 `SS` 는 평범한 셸 변수라 S 축 값(512)이 T 축과
OP-r2 로 남았다(`NQP`·`ORD` 는 env 접두라 무사).

```text
T30    slots 512   12.808      OP-r3  slots 128   12.988     1.4%
```

발자국 4배가 1.4% 이므로 T 축은 유효로 둔다. 저장소 구동기에는 `SS=128` 을
명시해 막았다. **부수 소득**: 발자국이 이 범위에서 거의 공짜라는 실측.

### (3) nqp=64 는 자원 한계로 무장 불가

```text
── 무장: … nqp=64 … (총 QP = 30 × 64)
extstore rdma_cm: create_cq failed (worker 0 qp 0): Cannot allocate memory
```

**원인 규명·수정 완료 (2026-08-07).** CQ 가 `2 × W × nqp` 로 잡혔는데
`outstanding` 은 워커 단위 스칼라라 W 개를 넘는 CQE 가 동시에 존재할 수
없다 — 순수 과할당이었고, `W = nqp × ORD` 라서 nqp² 로 커졌다. `2×W+8` 로
고친 빌드(sha 646ff2b7)에서 **nqp=64 의 QP 1,920 개가 전부 연결된다.**

```text
수정 후 nqp=64:  genie_connect OK (qps/worker=64 window=1024) ← create_cq 통과
                 extstore: reg_mr(worker bounce 7864320B) failed: I/O error
```

다만 다음 관문에서 막힌다 — in-flight 30,720 개가 요구하는 bounce 7.86 MB 가
SNP 공유 영역에 등록되지 않는다(slots 를 기능적 최소치 1024 로 낮춰도 동일).
**이건 과할당이 아니라 그 동시성의 실제 필요량**이므로, `Q64 · S64x4` 는
mcT=30 · slot=256 에서 여전히 측정 불가다.

### (4) 축 CSV 분류 누락 — O 축이 `etc.csv` 로 (해결)

분류 사슬에 라운드 2 이름 `SF-O` 만 있고 `SF3-O` 가 없었다. 값은 온전했고

## 7. 후속 — W 수정(sha 646ff2b7)과 그 영향

캠페인 종료 후 W 를 손잡이에서 없애고 `nqp × ORD` 파생으로 바꾸면서 큐
사이징도 고쳤다(CQ `2×W×nqp` → `2×W+8`, SQ `W+1` → `2×ORD+8`).
운영점 동일 조건 검증(`WFIX-OP`, 각 180초):

```text
워크로드  쓰기비중   캠페인    수정후      차이
GET          0%    12.873   12.862    −0.09%
MIX         10%    10.687   10.954    +2.50%
SET        100%     5.635    6.328   +12.30%
   err5 0 · write_failures 0 · read_failures 0 · engine_dead 0
   pac_fallback 0 · slot_acct_leak 0 · listen_disabled_num 0
```

**개선폭이 쓰기 비중에 단조 비례한다.** READ 는 ORD 로 묶여 큐를 얕게 쓰지만
WRITE 는 ORD 면제라 큐를 깊게 쓴다(`extstore.c:972`) — 과대한 SQ/CQ 의 비용을
쓰기 경로가 다 물고 있었다는 뜻이다.

### 캠페인 수치를 읽을 때

```text
GET  영향 없음 (−0.09%)
MIX·SET  전부 눌려 있던 값이다
  P·E·D·C·T   nqp·ORD 고정이라 CQ 512 로 균일 → 축 내부 형태는 유효,
              절대값만 낮다
  Q·O·S       CQ 가 셀마다 달랐다 → MIX·SET 은 GET 보다 더 교란됐다
```

즉 §4 재측정 권고는 GET 뿐 아니라 MIX·SET 때문에도 필요하다.

## 8. 관리자 결정 대기

```text
1. Q·O·S 재측정 (13구성) — W 수정 빌드로. §4 형태 효과 판정이 여기 걸려 있다
   P·E·D·C·T 는 큐 할당이 전 셀 동일했으므로 재측정 불요
2. ORD>16 재개 — CM clamp 수정 후 6점 (같은 파일이라 1과 함께 하면 된다)
3. nqp=64 재개 — bounce 7.86 MB 가 벽이다. mcT 를 낮추면 되지만 T 축과 교란
4. 운영점 이동 — E 축 2×512 (+7.7%), Q 축 nqp=1 (+2.6%, 단 §4 보류에 걸림)
5. P 축 MIX 붕괴(384·512, −31.9%) 원인 규명
```
