## 4. 선행 확인 — QP 천장과 그 원인

```text
A16-1     nqp=1    ORD=16     30 QP   UP
A128-1    nqp=8    ORD=16    240 QP   UP
A128-4    nqp=64   ORD=2   1,920 QP   UP     ← v3 검증 최대(896)의 2.1 배
A128-5    nqp=128  ORD=1   3,840 QP   실패
          create_cq failed (worker 0 qp 0): Cannot allocate memory
```

**자원 고갈이 아니다** — memlock 6.19 GB, HCA `max_qp` 131,072,
게스트 메모리 46 GB 여유. 그리고 실패가 **첫 번째 QP** 에서 났다(누적 고갈이면
중간에서 난다).

가르는 시험:

```text
MLX5_COHERENT_CQ=1  nqp=128 (3,840)   실패
MLX5_COHERENT_CQ=0  nqp=128 (3,840)   UP      ← coherent 를 끄면 뜬다
MLX5_COHERENT_CQ=1  nqp=96  (2,880)   UP
```

**천장은 coherent CQ 풀이고 2,880 과 3,840 사이다.** 이 빌드의 성질이다.

`COHERENT_CQ=0` 으로 우회하지 않기로 했다 — coherent 여부가 데이터 경로를
바꿔 다른 셀과 비교할 수 없다. 곱 128 행을 `nqp ≤ 64` 로 자르는 것이 설계
수정 사항이었다(미시행).

## 5. 캠페인 중 고친 계측 결함 셋

전부 **틀린 숫자가 측정값처럼 보이는** 형태였다 — 에러보다 나쁘다.

| 결함 | 증상 | 조치 | 검증 |
|---|---|---|---|
| 리셋 경합 | `p99 = 0` | 히스토그램 먼저 비우고 카운트 나중. 백분위를 히스토그램 합 기준으로 | 79.4 / 127.3 / 31.5 정상 출력 |
| 버킷 포화 | `p99 = 3276.70`(최상단 버킷) | `UINT64_MAX` 반환 → obwatch `CLIP` | A16-1-SET srv·bk 에서 확인 |
| 셀 구별 불가 | `stats` 에 nqp/ORD/read_slots 없음 | 노출 추가 | A16-2 부터 fingerprint 확인 |

세 번째는 genie 가 지적했다. **실험 A 는 그 셋으로만 셀이 갈리는데** 노출이
없어 19 셀을 기록해놓고 어느 구성이 어느 수치를 냈는지 양측 다 증명 못 하는
상태였다.

빌드 이력:

```text
aa55efd5   C1 전 구간
4abf804d   리셋 경합 + 버킷 포화 수정.  A16-1
be6b7804   fingerprint 노출 추가.        A16-2 이후
```
