## 3. 형태 효과 — 아직 열려 있다

곱과 발자국을 고정한 두 쌍이 같은 방향(QP 적고 깊은 쪽 우세)을 가리킨다.

```text
wire 16,  slots 64    Q1(1×16) 13.096 > O4(4×4)  12.806   +2.26%
wire 256, slots 512   S16x16   12.539 > S32x8    12.288   +2.04%
```

둘 다 노이즈 상한(2.04%) 경계라 **각각으로는 판정 불가**이고, 두 쌍이
같은 부호일 확률은 참효과가 0 이어도 50% 다. 보충의 `S64x4`(추세의 세 번째
점)와 `O4-r2`(쌍 1 직접 복제)가 들어오면 닫힌다. 사전 등록 예측:
`S16x16 > S32x8 > S64x4ㅤ≈12.0~12.1` 이면 형태 효과 확정.

## 4. 이번 캠페인에서 드러난 결함 3건

### (1) ORD>16 핀은 무장 불가 — 계획 6점 측정 불가

```c
extstore.c:644   .responder_resources = (uint8_t)ask, .initiator_depth = (uint8_t)ask
```

핀 값이 소프트 게이트가 아니라 **CM 협상 파라미터**로 들어간다. HCA 최대
16 을 넘는 depth 로 QP 가 서면 첫 READ 가 `remote invalid request (9)` 로
죽는다. `extstore.c:650` 주석의 "초과분은 SQ 에 쌓인다"는 실측으로 거짓이고,
`uint8_t` 캐스트라 ORD=256 은 0 으로 잘리기까지 한다.

측정 불가: `O32 O64 S1x256 S2x128 S4x64 S8x32`.
고치려면 CM 파라미터만 HCA 최대로 clamp 하고 소프트 게이트는 핀 값을 쓰면
된다(주석이 의도한 동작). **캠페인 중 바이너리 교체는 하지 않았다** —
지문 sha 가 바뀌면 앞선 셀 전부와 비교가 끊긴다.

### (2) 구동기 `SS` 누수 — T 축·OP-r2 발자국 4배

`sf-resume.sh:187` 의 `SS` 는 평범한 셸 변수라 S 축 값(512)이 T 축과
OP-r2 로 남았다(`NQP`·`ORD` 는 env 접두라 무사). 다만 **실측 영향 0.51%**
(T30 slots512 12.808 vs OP slots128 12.873)라 T 축은 유효로 둔다.
저장소 구동기에는 `SS=128` 을 명시해 막았다.

### (3) 축 CSV 분류 누락 — O 축이 `etc.csv` 로

분류 사슬에 라운드 2 이름 `SF-O` 만 있고 `SF3-O` 가 없었다. 값은 온전했고
`tools/sf-split.py` 로 재분리했다.

## 5. 유실과 보충

**부분 오염 셀 0개** — 보고된 셀은 전부 3/3 워크로드다.

```text

  GO 도착 시 bed 불일치 → genie 정당 거부        D4

  바이너리 한계 (§4-1)                           O32 · O64 · S1x256 · S2x128 · S4x64 · S8x32
```

(OP-r2 는 §4-2 때문에 가드로 못 쓴다).
